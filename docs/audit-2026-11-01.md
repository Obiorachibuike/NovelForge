# NovelForge audit — 2026-11-01 (partial)

This is an interim audit, not a certification or an exhaustive count of all defects. The application is **not production ready**. Work was prioritized around the Vercel build failure and existing generation workflows.

## Scope and architecture reviewed

Reviewed the README, package and lockfile, TypeScript and Next.js configuration, Vercel build configuration, environment example, generation API and SSE route, queue integration, generation engine, chapter, image and outline services, database selector and schema, deployment documentation, and existing tests. The app uses Next.js 14/Auth.js, SQLite for development, PostgreSQL with a synchronous worker-thread bridge in production, and pg-boss plus a separate long-lived worker for background jobs. Persistent storage and provider credentials must be configured externally. Two GitHub PRs were open (#23 and #5); no open issues were returned. PR #23 is draft and its claimed behavior was not verified in this audit.

## Fixes in this branch

- Generation SSE route: removed the attempted dispatch to a missing `streamEvents` method and kept the existing authenticated, replayable database-event stream. The route's previous undefined registry reference was the first Vercel type error.
- Generation registry lookups: replaced calls to nonexistent `has` with the existing `hasHandler` API. The prior calls also broke legacy job creation at runtime.
- Generation creation: read and validate the request body once through the size-limited JSON reader; previously the legacy path attempted to consume the request body twice.
- Outline generation: replaced an undefined variable with the calculated average chapter word budget. The error occurred while building a fallback before the provider was called, including for real-provider requests. Added a regression test.

## Open, high-priority findings

1. **Deployment fails:** TypeScript reports 40 errors, mostly in the incomplete universal generation integration. The production build fails during type checking. Examples include incompatible request types, missing registry imports, missing job ID and inconsistent queue execution interfaces. Type checking must not be disabled to conceal this.
2. **Universal generation is not production ready:** its persistence references columns not present in the migrations, writes incomplete event ownership data, and inserts jobs without the normal queue dispatch. Its migration registry uses placeholder job IDs and mismatched handler contracts; some alternate paths bypass normal chapter/cover validation. The SSE route does not provide a separate universal stream. A complete integration needs a coherent durable job contract, ownership, cancellation, recovery and provider tests; it has not been implemented here.
3. **Tests fail:** the baseline full test suite reported 17 failures out of 437 tests. Several expect demo chapter generation while the implementation explicitly refuses it; hosted generation and model catalogue tests also fail. The end-to-end workflow progressed past the outline error after the fix but still failed because chapter generation rejects an unavailable provider. These failures require investigation, not unconditional demo output in production.
4. **Dependency advisories:** `npm audit` reported 65 findings (3 critical, 8 high, 54 moderate). This is an advisory count, not a confirmed count of exploitable vulnerabilities. Direct dependencies with critical advisories include Next.js and Vitest; several suggested fixes are major upgrades. No blanket `npm audit fix --force` was run. Assess exploitability and upgrade/test deliberately.
5. **Deployment/infrastructure not validated:** PostgreSQL, pg-boss, external worker lifecycle, real AI providers, cloud storage, billing, email, serverless SSE timeouts and browser/mobile behavior were not tested against live services. Vercel cannot host a persistent worker within request-scoped functions; a separately hosted worker and shared persistent database are required. This audit did not verify that the PostgreSQL bridge is packaged correctly in a Vercel deployment.
6. **Audit coverage is incomplete:** not all routes, permissions, database paths, components, external integrations, or feature workflows were independently verified. No comprehensive vulnerability or accessibility assurance is implied.

Do not merge this branch as a complete production-readiness fix without resolving and validating the remaining blockers.
